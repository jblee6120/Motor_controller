01 / QUICK START

시작하기

  1. 실행: macOS에서 alm/launch.command를 더블클릭합니다. 또는 프로젝트 폴더에서 python3 alm/server.py를 실행합니다.
  2. 브라우저에서 http://127.0.0.1:8765/를 엽니다.
  3. 왼쪽 SYS.2 시스템 요구를 선택해 기존 요구사항을 살펴봅니다.
  4. 요구사항을 누르면 본문, 검증 기준, 상위 요구와의 링크, 점검 항목을 볼 수 있습니다.
  5. 사용이 끝나면 서버를 실행한 Terminal 창에서 Ctrl+C를 누르거나 창을 닫습니다.

처음 데이터에는 SYS.1 요구 16건, SYS.2 요구 46건, 추적 링크 102건과 프로젝트 문서 3건이 들어 있습니다. 이후 작성한 내용은 자동 저장됩니다.

02 / NAVIGATION

화면 구성

대시보드

전체 산출물 수와 ASPICE 프로세스 지도를 봅니다. 단계 카드를 누르면 해당 목록으로 이동합니다.

산출물

모든 항목을 ID·제목·본문으로 검색하고 종류와 상태로 걸러 봅니다.

추적성

항목 사이의 관계 전체를 보고, 출발 항목에서 대상 항목으로 이동합니다.

점검

누락된 상위 링크, TBD, 실현 가능성 평가 대기 등을 모아 봅니다.

왼쪽 PROCESS MAP은 MAN, SYS, HWE, SWE, VAL, SPL, SUP 단계를 보여줍니다. 단계를 선택하면 그 단계의 역할과 등록된 산출물이 표시됩니다.

오른쪽 위 새 산출물은 항목 생성, JSON 내보내기는 현재 데이터를 파일로 내려받는 기능입니다.

03 / WORK ITEMS

산출물 만들기·편집

새 항목 만들기

  1. 왼쪽에서 만들 단계(예: SYS.3 시스템 아키텍처)를 선택합니다.
  2. ＋ 새 산출물을 누르고 산출물 종류를 고릅니다.
  3. 제목과 내용을 적고 상태·우선순위·분류를 정합니다. 종류에 따라 검증 기준, 시험 절차, 실행 형상 등 추가 입력칸이 나타납니다.
  4. 생성을 누릅니다. ID가 자동으로 생성되며 상세 화면이 열립니다.

지원 종류: 요구사항, 아키텍처, 설계, 시험 명세, 시험 결과, 문서, 변경 요청, 문제 보고. 생성 후 ID와 프로세스·종류는 바꿀 수 없습니다.

기존 항목 수정

목록에서 항목을 연 뒤 편집을 누릅니다. 수정 후 저장하면 개정 번호가 올라갑니다. 이전 내용은 이력에서 확인할 수 있습니다.

항목 삭제 대신 Obsolete: 더는 사용하지 않는 요구사항은 상태를 Obsolete로 바꾸세요. ID와 기존 연결이 남아 추적 이력을 잃지 않습니다.

04 / TRACEABILITY

추적 관계 연결

  1. 산출물 상세에서 ＋ 연결을 누르거나 추적성 → ＋ 관계 추가를 누릅니다.
  2. 출발 항목, 관계, 대상 항목을 선택합니다.
  3. 관계 저장을 누릅니다. 상세 화면에는 양방향으로 표시됩니다.
관계사용 예
derived_fromSYS-REQ-002 → STK-REQ-015: 시스템 요구가 이해관계자 요구에서 도출됨
implementsHWE-DES-001 → HWE-REQ-001: 설계가 요구를 구현함
allocated_to시스템 기능을 아키텍처 요소에 할당함
verifiesTC-SYS5-001 → SYS-REQ-002: 시험 명세가 요구를 검증함
result_ofRUN-001 → TC-SYS5-001: 실행 결과가 시험 명세에 대응함
related_to변경 요청 또는 문제를 관련 산출물에 연결함

표의 일부 ID는 방향을 설명하기 위한 예시입니다. 아직 만들어지지 않은 항목은 실제로 생성한 뒤 연결하세요.

전형적인 흐름: 이해관계자 요구 ← 시스템 요구 ← HW/SW 요구 ← 설계, 그리고 시험 명세 → 검증 대상 요구, 시험 결과 → 시험 명세.

05 / VERIFICATION

시험 명세·결과 기록

시험 명세와 시험 결과를 별도 항목으로 만듭니다. 하나의 시험 명세를 여러 번 실행하더라도 명세를 복제할 필요는 없습니다.

  1. 검증 단계(예: SYS.5)에서 종류 시험 명세를 만듭니다. 사전 조건, 시험 절차, 기대 결과·판정 기준을 적습니다.
  2. 시험 명세에서 verifies로 대상 요구사항을 연결합니다.
  3. 실제 시험을 수행한 뒤 종류 시험 결과를 만듭니다. PASS/FAIL/BLOCKED, 실행일, HW Rev·FW Commit·모터 설정, 증거 파일 경로를 적습니다.
  4. 시험 결과에서 result_of로 해당 시험 명세를 연결합니다.

시험 결과의 PASS는 기록된 HW/SW 형상과 시험 조건에서의 결과입니다. 형상이 바뀌면 변경 영향을 검토하고 필요한 시험을 다시 수행하세요.

06 / QUALITY

점검과 승인

점검 화면의 목록을 눌러 해당 항목으로 이동합니다. 현재 초안에 TBD와 미평가 경고가 많이 표시되는 것은 예상된 상태입니다. 값을 임의로 채워 경고만 없애기보다는 실제 목표·시험 조건을 결정한 뒤 기록하세요.

SYS.2 요구사항은 다음 조건이 남으면 Approved로 저장할 수 없습니다.

  • 본문 또는 검증 판정 기준에 TBD가 남음
  • 미결정 항목이 남음
  • 검증 방법이나 판정 기준이 비어 있음
  • 기술 실현 가능성이 Assessed가 아님
  • 상위 이해관계자 요구와 derived_from 관계가 없음

SYS.1 항목에 파생된 SYS.2 요구가 없거나 시험 명세·결과에 연결이 없으면 점검 화면에 경고가 표시됩니다.

07 / PROCESS WALKTHROUGH

단계별 사용 예

단계GUI에 기록할 산출물연결할 대상
MAN.3 / SYS.1프로젝트 목표, 이해관계자 요구SYS.2 시스템 요구
SYS.2 / SYS.3시스템 요구, 아키텍처, 인터페이스상위 필요와 HW/SW 할당
HWE.1~4HW 요구·회로/PCB 설계·검증 명세와 결과시스템 요구 및 HW 설계/시험
SWE.1~6SW 요구·아키텍처·상세 설계·단위/통합/요구 검증상위 요구 및 시험
SYS.4 / SYS.5HW/SW 통합과 시스템 요구 검증시스템 요구와 실행 증거
VAL.1 / SPL.2사용 목적 확인, 릴리스 형상최종 시험 결과와 형상
SUP.8~10형상, 문제 보고, 변경 요청영향받는 요구·설계·시험

예를 들어 CAN 통신 상실 요구를 다룬다면 SYS.2 요구를 확인하고, SYS.3 기능 할당, HWE/SWE 세부 요구, SYS.5 시험 명세를 순서대로 추가한 뒤 관계로 연결합니다. 하드웨어와 소프트웨어 작업은 서로 병행할 수 있습니다.

08 / DATA & BACKUP

저장·백업·원본 파일

즉시 저장

GUI에서 저장한 내용은 alm/data/alm.sqlite3에 반영됩니다.

Git 관리용 파일

alm/data/workspace.json에 항목·관계·변경 이력이 자동 기록됩니다.

수동 백업

앱 오른쪽 위 JSON 내보내기를 눌러 현재 항목과 관계를 내려받을 수 있습니다.

다른 컴퓨터

SQLite 파일이 없으면 workspace.json을 바탕으로 데이터베이스를 다시 만듭니다.

Git에서 workspace.json을 업데이트했다면 ALM 화면을 새로고침하세요. 새 JSON을 감지해 SQLite에 반영하고, 이전 SQLite는 alm/data/alm.sqlite3.bak-*로 백업합니다. 두 저장소의 변경이 충돌하면 자동 반영을 멈추고 오류를 표시합니다.

중요: 기존 moteus_c1_aspice_draft의 YAML·CSV·Markdown은 초기 자료로 보존됩니다. GUI 수정 내용이 그 파일들에 자동 반영되지는 않습니다. GUI 사용 후에는 workspace.json을 관리 기준으로 삼으세요.

원본용 validate_requirements.py는 GUI의 최신 데이터를 검사하지 않습니다. GUI에서 변경한 내용은 점검 화면을 확인하세요.

09 / HELP

자주 묻는 질문

YAML이나 CSV를 직접 열어야 하나요?

일상적인 요구사항 작성·수정·연결에는 필요하지 않습니다. 기존 파일은 초기 자료로 남아 있습니다.

새 산출물의 ID를 직접 정할 수 있나요?

현재 버전에서는 프로세스와 종류에 맞춰 자동 생성됩니다. 생성 뒤 변경할 수 없습니다.

파일 자체를 첨부할 수 있나요?

현재 GUI는 파일 업로드 저장소가 없습니다. KiCad·Simulink·시험 증거 파일은 프로젝트 폴더에 보관하고, 해당 산출물의 내용 또는 증거 경로 칸에 경로·형상을 적으세요.

다른 사람이 네트워크로 접속할 수 있나요?

기본 실행은 127.0.0.1에만 바인딩되어 같은 컴퓨터에서만 접속할 수 있습니다.

ASPICE 인증 도구인가요?

개인 프로젝트의 프로세스와 추적성 관리를 돕는 도구입니다. 공식 평가나 인증을 대신하지 않습니다.
